## 수정과 보존 방식

- 예약 적용은 하나의 readwrite 트랜잭션에서 최신 고용·조직·이력·동일일 발령을 다시 읽고 검증한다. 같은 날의 기존 중복 예약은 임의로 하나를 선택하지 않고 모두 보류한다.
- 신규 예약은 원천 조직 이력과 고용상태를 스냅샷으로 기록한다. 예약 이후 조직·고용상태·현재 이력·유효기간이 바뀌면 자동 적용하지 않는다. 스냅샷이 없는 기존 예약에는 기존 before 값, 회사 소속, 상태, 기간 및 충돌 검사를 적용하며 과거 스냅샷을 지어내지 않는다.
- 충돌 시 기존 Person/Employment/Assignment/발령의 원래 before·after·사유를 보존하고 reviewReason 및 한 건의 검토 감사로그만 추가한다. 반복 초기화는 이를 재적용하거나 중복 기록하지 않는다.
- 직원 상세 타임라인에 검토 사유를 표시한다. 보류를 강제 해제하거나 자동 병합하는 기능은 추가하지 않았다.
- 예약/즉시 발령 등록은 동일일 발령의 존재를 확인하고 트랜잭션 안에서 다시 중복을 확인한다. 동시에 같은 날짜의 예약을 넣으면 하나만 저장된다.
- 실제 Chrome에서 재현된 근태의 오래된 탭 덮어쓰기를 수정했다. 월별 revision과 일별 updatedAt, 저장 직전 원본 레코드, 급여 상태, 회사의 근태 마감 상태를 검사하고 충돌 시 트랜잭션 전체를 취소한다.
- DB 이름·버전·기존 PK를 유지했다. 새 필드는 선택적이며 기존 백업과 호환된다. 사용자 브라우저나 배포 사이트의 데이터를 열거나 초기화하지 않았다.
