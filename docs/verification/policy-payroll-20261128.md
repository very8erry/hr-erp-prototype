- 버전: 2026-11-28 / HRIS 0.7.9 변경안
- 기준 커밋: `3fc7b8ce91cb2fe2b11716e11fa86b631a8984dc`
- 변경 브랜치: `codex/policy-payroll-workflow`
- 관련 요구: PAY-04, PAY-11, PAY-12, SET-02, SET-03, SET-06, OPS-14, DOC-01, DOC-04, DOC-08 및 2026-11 규정·계약 연결 요청
- 이 문서는 실행한 검증 범위를 기록한다. 전체 과거 요구사항 170건의 개별 브라우저 검증 완료를 의미하지 않는다.

## 실제 변경

1. `PolicyDocument.standards`를 재사용하는 급여설정 규정 기준표를 추가했다. 원문·첨부 읽기, 기준 추출, 실제 근무일정/계약/지급일/업무 설정 대조, 원천 설정 수정, Markdown 내보내기를 제공한다. 명시값과 산출값, 승인 여부, 기간/조건을 구분한다. 미확정 문서는 일치로 인증하지 않는다. 동일 불일치 팝업은 중복 표시하지 않고 내용이 달라지면 다시 표시한다.
2. `AttendanceSetting.contracts`에 기간별 계약을 보존한다. 임시 계약 종료 후 기존 계약의 남은 기간도 보존한다. 209는 통상임금 환산시간이며 달력상 실제 근무예정시간과 구분한다. 주휴·공휴일·유급휴가·실근로·무급 부재를 구분하고 급여에 계약/근태 스냅샷을 저장한다.
3. 기본 연장·야간·휴일 수당은 일별 계약 환산시간과 육아기 단축 회사 지급비율에 따라 단가를 나누어 계산한다. 상세 내역에 시간·시급·환산시간·산출금액을 표시한다. 여러 단가에 걸친 사용자 지정 산출식의 일괄 적용은 오류로 차단하고 적용 단위 검토를 요구한다.
4. 계산 시 자동 검증을 실행한다. 별도 검증 버튼을 제거했다. 원천시간과 저장된 근태 버전은 같은 트랜잭션에서 소비한다. 오류는 확정을 차단하고 경고는 검토 대상으로 표시한다.
5. 미지급 확정/마감 급여는 정정 전 입력·결과·상태를 감사로그에 보존한 후 잠금을 해제한다. 지급완료 원본은 변경하지 않고 이후 미확정 월에 추가 지급/환수/과세분류 정정을 기록한다. 중복 적용과 원본 금액 불일치를 거부한다. 원천세·보험·연말/퇴직정산 영향은 따로 표시한다.
6. 정산 항목을 개별 선택하고 소득세/지방세, 건강/요양의 공통 조건을 명시적으로 적용한다. 각각의 확정 정산금액을 사용하며 다른 세목 금액을 복제하지 않는다.
7. 공통 고정금액과 직원별 금액을 구분한다. 공통 금액은 지급항목·대상 직원·조건·시행월을 지정한다. 보험/세금 공제와 연장/야간/휴일/무급 차감은 공통 금액 대상에서 제외한다. 직원별 명시 금액은 0원을 포함해 우선하며 합산하지 않는다.
8. 공식 원문의 위치·키워드·값·기간을 검토하여 승인한 요율을 계산에 사용한다. 승인 전 기존 규칙을 유지하고 기간이 겹치는 승인은 차단한다. 미래 규칙이 과거월에 적용되지 않도록 한다.
9. 비과세 인정분과 초과/미충족 과세분을 분리한다. 예: 요건을 충족한 식대 30만원 중 20만원만 비과세, 10만원은 항목의 보험 포함 설정에 따라 보수 후보에 포함한다. 공단 결정 연금/건보 보수를 자동으로 대체하지 않는다.
10. 근로소득간이지급명세서 메뉴에 지급완료 원천 불러오기, 수정 표, CSV/XLSX/JSON 왕복, 샘플, 불변 초안 버전, 2026 공식 반기 양식 PDF를 추가했다. 회사 대표 전화번호를 사용하며 가상식별번호만 허용한다.
11. 초기화 범위를 선택한다. 재구성은 내려받은 백업 확인 후 출처가 확인된 더미에만 적용한다. 수기/가져온 자료·사용자 생성 급여월은 보호한다. 재구성 급여는 검증 완료·미확정 상태이며 과거 지급 상태로 자동 복귀하지 않는다.
12. 구 설명서 2종을 읽고 변경된 기능을 대조해 현재 사용설명서(6쪽), 이슈 처리 안내(4쪽)를 만들었다. 개인 내역 다운로드와 법정 명세서 자동 교부는 별개라는 실제 경로를 명시했다. 설계 HTML·타입 사전·규정 참고 파일을 갱신했다.

실제 브라우저에서 신고자료 불러오기가 화면의 이전 급여월 목록을 사용해 최신 지급자료를 놓칠 수 있는 결함을 발견했다. 조회 버튼에서 최신 원장을 직접 조회하도록 수정한 후 통과했다.

월을 나눠 더미 재구성하면 기존 계약 배열 때문에 뒤에 선택한 임신기 단축 계약이 빠지는 결함을 재현했다(STANDARD로 조회되어 실패). 선택 월의 생성 계약만 추가하도록 수정하고 기존 계약의 완전 일치와 단축 계약 연결을 재검증했다. 수기 계약은 자동 재작성하지 않는다.

초기 검증에서 잡은 문제도 숨기지 않는다. 정정 이력은 IndexedDB PK 순서여서 시간순 조회로 수정했고, 테스트는 사유로 해당 보존본을 식별한다. 더미 계산에서 추가 수당 기본설정 병합을 보완했다. PDF의 식별자 열과 부표 일련번호 위치를 수정했다. 브라우저 테스트는 다운로드 형식 선택 후 실제 다운로드 버튼을 누르도록 수정했고, Radix 팝업의 `dialog` 역할을 사용했다. 빌드가 생성한 HTML로 개발 서버가 새로고침되는 간섭은 테스트 포트 독점/출력폴더 감시 제외/단독 실행으로 제거했다.

## 출력물·보안 확인

- 공식 서식은 원본 표 배경의 복사본에 값을 기입한다. 7명/3페이지의 칸, 일련번호, 한글, 전화번호, 금액을 렌더링해 확인한다. 자동 기관 접수 파일이라고 표시하지 않는다.
- 사용설명서 6쪽과 이슈 안내 4쪽을 렌더링해 검토했다. 과거 PDF는 보존하고 최신 파일을 별도로 제공한다.
- 변경한 텍스트에서 인증키 형태·개인 홈 경로·Mac 호스트명 패턴 발견 없음. Git 추적 텍스트에서도 개인 홈 경로·인증키 패턴 발견 없음. 배포 번들의 경로 패턴 2건은 공식 사이트 URL과 PDF 라이브러리의 고정 가상 경로로 확인했다. 새 PDF에 작성자/개인 경로 메타데이터 발견 없음. 이 검사는 과거 모든 Git 커밋의 비밀정보 스캔을 재수행했다는 의미가 아니다.
- 정책 문서·설계 HTML은 열람용이며 실제 계산은 구조화 원장을 사용한다. 164개 소스 파일의 지문을 설계에 기록하고 불일치 시 릴리스 검사를 실패시킨다. 의미 검토까지 자동 보장하지는 않으므로 설명·기능 대응표 검토도 필요하다.

## 남은 범위와 정책 결정

1. **확인된 미지원**: 2027 월별 간이지급명세서 목록은 지원하지만 새 공식 월별 PDF 양식은 검증하지 못해 출력을 차단한다. 2026 반기 양식을 2027에 재사용하지 않는다.
2. **회사 규정 결정**: 주휴 경계 주의 자료 누락/지원금 구간, 승인되지 않은 원문, 특별 근로조건, 여러 단가에 걸친 사용자 산출식은 확인/검토 대상으로 남는다. 금액을 임의로 지급·공제하거나 규정을 자동 승인하지 않는다. 기본 산출식은 계약별 단가 계산을 지원한다.
3. **실행하지 않은 외부 업무**: 기관 전자신고 접수, 실제 은행 이체, 문자/메일 도달은 수행하지 않았다. 실습 식별번호 자료를 실제 기관에 제출하지 않는다.
4. **승인 필요**: 사용자 실제 저장 데이터의 재구성은 백업과 화면의 명시적 실행 선택이 필요하다. 배포가 기존 IndexedDB를 일괄 초기화하지 않는다.
5. **병합·배포 대기**: 최신 요청 원문의 “검증 결과를 보고하고 사용자 승인 후 main 병합 및 배포”에 따라 PR까지만 진행한다. 아직 배포하지 않았으므로 새 변경의 운영 사이트 검증은 승인 후 배포 단계에서 수행한다.
