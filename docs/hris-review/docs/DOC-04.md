# DOC-04　상태 전이·업무 규칙 정의서

v1.0 · 2026-11-19 · b4aeb300270a62273d3d5f0c2fea87f2a09ba800

독자　HR·개발·QA

목적과 범위　행 확정과 회사 월 마감, 급여 Run 상태, 발령 검토 사유를 구별한다.


| 규칙 | 업무 | 거부·허용 및 후속 조건 |
|---|---|---|
| BR01 | 직원 신규 고용의 원자적 등록 | 이름 경고는 검토 표시 후 제출한다. 이미 사용한 사번이면 입력을 바로잡는다. |
| BR02 | 수락 오퍼의 단일 입사전환 | 오퍼 조직의 회사와 기존 전환 여부를 확인한다. 거부되면 후보 상태를 유지한다. |
| BR03 | 효력일 기준 조직 이력 보존 | 동일일 충돌이나 소속 불일치면 재검토한다. 예약 이후 원천 이력이 바뀌면 검토 사유를 확인한다. |
| BR04 | 동시 수정 근태의 원본 보존 | 재직기간·중복·시간 범위·확정 여부를 확인한다. 오래된 화면 오류면 다시 조회해 최신값과 대조한다. |
| BR05 | 대상 근태 누락 시 마감 거부 | 대상자에게 누락 행이 있으면 보완한다. 급여월 생성보다 먼저 마감하면 대조할 Entry 범위가 달라진다. |
| BR06 | 귀속월별 고용 대상의 생성 | 입사예정·월 밖의 고용은 제외된다. 원장에 보상·배치 이력이 없으면 건너뛰므로 제외 명단 검토가 필요하다. |
| BR07 | 계산 입력과 산출 결과의 분리 | 개별 입력과 계산 결과를 대조한다. 확정·마감·지급 완료월 재계산은 거부된다. |
| BR08 | 최신 근태 입력으로만 검증 완료 | 오류가 0이면 검증 완료가 가능하다. 경고만 있는 경우의 최종 승인 책임은 별도 정책이다. |
| BR09 | 검증 완료 후 급여 확정 | VALIDATED와 stale 해제가 전제다. 담당자 교차 승인은 확인되지 않았다. |
| BR10 | 근태 마감 후 급여 마감 | 선행 단계가 빠지면 마감 버튼 또는 저장 경로가 거부한다. |
| BR11 | 마감 급여의 지급 완료 기록 | CLOSED에서만 허용한다. 이 화면의 완료 표시는 은행 거래 성공을 증명하지 않는다. |
| BR12 | 지급 후 원본 연결 차액 정정 | 확정 이후 원 Run의 입력 수정·재계산이 차단된다. 별도 소급 항목의 금액 입력만으로 정정 원장과 승인 이력이 성립하지 않는다. |
| BR13 | 확정 퇴직정산 잠금 | 퇴사일 미등록 또는 확정 건 재계산을 거부한다. 계산 기초와 수기 보정을 검토한다. |
| BR14 | 개인·연도별 정산 차액 저장 | 최종세액이 비어 있으면 확정할 수 없다. 입력 수정은 사유를 남긴다. |
| BR15 | 원천세 초안의 소득구분별 대사 | 퇴사월·일용 구분과 검토 완료 여부를 확인한다. 전자 신고와 접수번호는 외부에서 관리한다. |
| BR16 | 취득·상실 양식 내보내기 | 취득은 입사월, 상실은 퇴사월로 대상을 고르고 상실일에 퇴사 다음날을 채운다. 기관 접수 여부는 외부 확인이다. |
| BR17 | 백업 복원 원자성 | v1에서 안전하게 변환할 수 없는 Person이 있으면 전체 복원을 거부한다. |
| BR18 | 실자료 내보내기 보호 | 암호화 백업과 권한 승인 기준은 업무 책임자가 선택한다. |
| BR19 | 지급 상태와 로그의 일관성 | 동일 요청의 재시도는 중복 로그를 만들지 않아야 한다. |
| BR20 | 가상 실행 로그의 격리 | 훈련용 DB와 시나리오 ID를 사용한다. |
| BR21 | 버전 이전 시 사용자 이메일 보존 | 업무상 승인된 변환 대상만 갱신한다. |


## 급여월 전이


| 이전 | 조작·조건 | 이후·쓰기 |
|---|---|---|
| 열린 Run | 계산·대상 존재 | CALCULATED / 항목·결과·시각 |
| 열린 Run | 검증 시 전체 재계산 | 오류 0 → VALIDATED, 오류 있음 → CALCULATED |
| VALIDATED | stale이 아니면 확정 | CONFIRMED / confirmedAt |
| CONFIRMED | 회사에 월 근태 마감 시각 있음 | CLOSED / closedAt |
| CLOSED | 지급 완료 버튼 | PAID / paidAt |
| 열린 Run | 입력 수정·근태 변경 | DRAFT / 결과 무효화 범위는 DOC-02 P04·P12 |
| CONFIRMED·CLOSED·PAID | 수정·재계산 | 거부. 문서화된 역전이 없음 |


근태 행은 confirmedAt으로 잠기며 월 마감은 별도 회사 필드다. 발령은 SCHEDULED로 등록한 뒤 적용 시 APPLIED가 된다. 충돌 검토는 별도 상태 열거값이 아니라 SCHEDULED에 reviewReason이 남는 경우다. 기존 Assignment의 효력 종료와 신규 이력 생성은 applyEvent 쓰기 거래에 포함된다. 연말정산은 미입력 최종세액을 0원과 구분하며 금액이 null이면 확정할 수 없다.
