## A01　근태 수정 뒤 과거 금액 검증

A · P0　·　요구 R08　·　근거 evidence/payroll-probe.json

발생 조건　월 근태 2→10시간 수정 후 수당 반영 없이 검증

현재 처리와 원인　계산은 Entry 시간을 읽고 월 근태의 최신 revision을 Entry에 찍는다. validate가 syncAttendance를 호출하지 않는다.

영향　총지급액 424만 원이 VALIDATED. 동기화한 동일 입력은 448만 원. 해당 가상 직원의 차이 24만 원.

개선 순서　계산 전에 연동 입력의 원천 버전을 확인하고 불일치면 검증을 거부한다. 반영 때만 버전을 기록한다.

대안　계산 직전 자동 반영도 가능하나 수기 수당 보존·우선순위를 먼저 정해야 한다.

완료 조건　2→10시간 수정 뒤 동기화 전 확정 불가, 동기화 후 448만 원. 수기 전용 행은 별도 근거 유지.

## A03　상태와 감사로그의 부분 저장

A · P1　·　요구 R09　·　근거 src/infrastructure/db/indexedDb.ts:822

발생 조건　상태 쓰기 성공 후 로그 쓰기가 실패하거나 두 탭이 동일 Run에 접근

현재 처리와 원인　setPayrollRunStatus는 조회·상태 put·감사 put을 분리한다. validatePayrollRun에도 분리 쓰기가 있다.

영향　성공 여부를 다시 확인할 때 확정 표식과 증적이 달라질 수 있다. 가상 DB에서 로그 쓰기를 중단하자 CONFIRMED 상태만 남고 해당 확정 로그는 없었다.

개선 순서　같은 readwrite 거래 안에서 최신 상태 재조회·전이·로그를 커밋한다.

대안　별도 보정 로그는 도입이 쉽지만 중간 불일치와 재시도 복잡성이 남는다.

완료 조건　로그 쓰기 중단 시 양쪽 모두 원복, 동일 요청 재시도 후 전이 로그 한 건.

## A04　근태 마감 중간 상태

A · P1　·　요구 R05　·　근거 src/infrastructure/db/indexedDb.ts:933

발생 조건　행 확정 이후 회사 마감 표식 저장 중단

현재 처리와 원인　confirmRecords와 회사 표식 put을 순서대로 별도 커밋한다.

영향　표식 쓰기를 중단하자 336개 행은 확정되고 월 표식은 비어 있었다. 재시도하면 월 마감은 완료됐다.

개선 순서　행·회사 표식·로그를 한 거래에서 확정하고 대상 집합을 재검사한다.

대안　기존 두 단계를 유지하면 재시도와 중간 상태의 표시 규칙이 필요하다.

완료 조건　중간 실패 후 행과 월 표식 모두 이전 상태, 재시도하면 단일 완료.

## B03　전체 백업에 인사정보 포함

B · P1　·　요구 R18　·　근거 src/app/DataToolbar.tsx:14

발생 조건　전체 JSON을 내보내 다른 기기 또는 공유 폴더로 이동

현재 처리와 원인　DataToolbar가 exportDatabase 결과를 JSON.stringify해 파일로 만든다. 로그에도 변경 전후 값이 들어갈 수 있다.

영향　원장과 첨부·급여 자료에 대한 파일 단위 접근 통제가 필요하다. 실제 유출 관찰 없음.

개선 순서　실자료 검토 전 최소 필드 추출·암호화 내보내기·복원 권한을 설계한다.

대안　가상 데이터 전용 유지가 가장 단순하지만 실제 자료 검토 목적은 제한된다.

완료 조건　가상 샘플로 민감 필드 목록을 대조하고 권한 없는 내보내기와 키 없는 복원 차단.

## C01　지급 후 차액 귀속·승인

C · P1　·　요구 R12　·　근거 src/infrastructure/db/indexedDb.ts:822

현재 처리와 원인　PAID 잠금과 retroPay 입력은 있으나 원 지급 건 연결·승인·기간 정책이 필요하다.

영향　과거 장부 보존과 당월 지급·신고 대사에 영향.

대안　다음 달 수기 조정은 빠르지만 원인과 중복 지급 추적이 어렵다.

완료 조건　원 Run의 금액·시간 해시 유지, 동일 조정 중복 방지, 차액과 당월 지급 합계 대사.

## C02　연간 집계 포함 상태

현재 처리와 원인　listYearEndTaxCases가 DRAFT만 제외한다. 잠정 검토와 최종 증빙에 필요한 범위가 다를 수 있다.

완료 조건　CALCULATED·CLOSED·PAID 혼합 자료에서 승인한 상태별 합계와 화면 표시 일치.

## D01　가상 시뮬레이션 기록

D · P3　·　요구 R20　·　근거 src/app/App.tsx:96

발생 조건　향후 AI가 가상 담당자 업무를 반복 수행할 때

현재 처리와 원인　현재 메뉴가 비활성이다. 기존 HR_ADMIN 문자열은 사용자별 인증 근거로 쓰기 어렵다.

영향　실자료와 훈련자료 혼입 및 개인 행동에 대한 과도한 해석을 방지할 설계가 필요하다.

개선 순서　별도 가상 DB·시나리오 ID·규칙 버전·행동 이벤트를 기록한다. 화면 수집은 기본 제외한다.

대안　화면 전체 기록은 문맥이 많으나 식별 가능성과 보관 부담이 증가한다.

완료 조건　동일 fixture와 규칙으로 결과 재현, 로그에 실제 사번·연락처·자유 입력·화면 픽셀 미포함.

## A02　구버전 직원 이메일 보존 실패

A · P1　·　요구 R21　·　근거 evidence/legacy-probe.json / indexedDb.ts:224–231

발생 조건　requestedV078 표식이 없는 v6 가상 DB에 사용자 이메일을 넣고 initialize

현재 처리와 원인　initializeRequestedV078이 비어 있지 않은 모든 Person.email의 도메인을 바꾼다.

영향　기존 test-hris-v7의 동일성 검사가 실패하고 별도 입력 custom@fixture.invalid도 custom@lemonpai314.com으로 바뀌었다.

개선 순서　사용자 원장을 유지하고 확인된 교육용 seed에만 보강을 적용한다. 불명확하면 변경을 보류한다.

대안　교육용 도메인을 표시 시점에만 치환하면 원장은 보존되나 출력·화면 정책을 구분해야 한다.

완료 조건　표식 유무와 사용자 지정 이메일 유무를 교차한 fixture에서 사용자 주소 및 회사 설정 보존. 재초기화 시 동일.


A03·A04는 fault-probe.json의 강제 중단 조건에서 재현됐다. P0는 액수 불일치가 재현된 경로다. P1은 지급·감사 보존 또는 실자료 검토의 선행 조건이다. P2는 누계를 최종 증빙으로 사용하기 전, P3는 가상 실험 확장 전 결정한다. 예상 효과의 금액·빈도·시간 절감은 측정하지 않았다.
