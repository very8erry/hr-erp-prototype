# DOC-10　설계 결정 기록

v1.0 · 2026-11-19 · b4aeb300270a62273d3d5f0c2fea87f2a09ba800

독자　PM·HR 책임자·개발

목적과 범위　현재 코드로 확인 가능한 선택과 제안 상태인 결정을 구분한다. 과거 설계자의 의도는 추정하지 않는다.

## ADR-01　근태 수정 뒤 과거 금액 검증

상태　제안 · 연결　A01 / R08

결정 배경　월 근태 2→10시간 수정 후 수당 반영 없이 검증

권장안　계산 전에 연동 입력의 원천 버전을 확인하고 불일치면 검증을 거부한다. 반영 때만 버전을 기록한다.

대안과 비용　계산 직전 자동 반영도 가능하나 수기 수당 보존·우선순위를 먼저 정해야 한다.

인수 기준　2→10시간 수정 뒤 동기화 전 확정 불가, 동기화 후 448만 원. 수기 전용 행은 별도 근거 유지.

## ADR-02　상태와 감사로그의 부분 저장

상태　제안 · 연결　A03 / R09

결정 배경　상태 쓰기 성공 후 로그 쓰기가 실패하거나 두 탭이 동일 Run에 접근

권장안　같은 readwrite 거래 안에서 최신 상태 재조회·전이·로그를 커밋한다.

대안과 비용　별도 보정 로그는 도입이 쉽지만 중간 불일치와 재시도 복잡성이 남는다.

인수 기준　로그 쓰기 중단 시 양쪽 모두 원복, 동일 요청 재시도 후 전이 로그 한 건.

## ADR-03　근태 마감 중간 상태

상태　제안 · 연결　A04 / R05

결정 배경　행 확정 이후 회사 마감 표식 저장 중단

권장안　행·회사 표식·로그를 한 거래에서 확정하고 대상 집합을 재검사한다.

대안과 비용　기존 두 단계를 유지하면 재시도와 중간 상태의 표시 규칙이 필요하다.

인수 기준　중간 실패 후 행과 월 표식 모두 이전 상태, 재시도하면 단일 완료.

## ADR-04　전체 백업에 인사정보 포함

상태　제안 · 연결　B03 / R18

결정 배경　전체 JSON을 내보내 다른 기기 또는 공유 폴더로 이동

권장안　실자료 검토 전 최소 필드 추출·암호화 내보내기·복원 권한을 설계한다.

대안과 비용　가상 데이터 전용 유지가 가장 단순하지만 실제 자료 검토 목적은 제한된다.

인수 기준　가상 샘플로 민감 필드 목록을 대조하고 권한 없는 내보내기와 키 없는 복원 차단.

## ADR-05　지급 후 차액 귀속·승인

상태　제안 · 연결　C01 / R12

결정 배경　지급 완료 뒤 전월 수당 누락 발견

권장안　Payroll 책임자가 귀속월·지급월·승인자·취소 방식을 결정하고 원 행과 연결한 차액 장부를 제안한다.

대안과 비용　다음 달 수기 조정은 빠르지만 원인과 중복 지급 추적이 어렵다.

인수 기준　원 Run의 금액·시간 해시 유지, 동일 조정 중복 방지, 차액과 당월 지급 합계 대사.

## ADR-06　연간 집계 포함 상태

상태　제안 · 연결　C02 / R14

결정 배경　검증·계산 중인 월이 연말정산 조회에 포함되는 시점

권장안　HR·세무 검토자가 가집계와 확정 제출용 상태 집합을 승인한다.

대안과 비용　마감월만 조회하면 보수적이지만 진행 중 누계가 보이지 않는다.

인수 기준　CALCULATED·CLOSED·PAID 혼합 자료에서 승인한 상태별 합계와 화면 표시 일치.

## ADR-07　가상 시뮬레이션 기록

상태　제안 · 연결　D01 / R20

결정 배경　향후 AI가 가상 담당자 업무를 반복 수행할 때

권장안　별도 가상 DB·시나리오 ID·규칙 버전·행동 이벤트를 기록한다. 화면 수집은 기본 제외한다.

대안과 비용　화면 전체 기록은 문맥이 많으나 식별 가능성과 보관 부담이 증가한다.

인수 기준　동일 fixture와 규칙으로 결과 재현, 로그에 실제 사번·연락처·자유 입력·화면 픽셀 미포함.

## ADR-08　구버전 직원 이메일 보존 실패

상태　제안 · 연결　A02 / R21

결정 배경　requestedV078 표식이 없는 v6 가상 DB에 사용자 이메일을 넣고 initialize

권장안　사용자 원장을 유지하고 확인된 교육용 seed에만 보강을 적용한다. 불명확하면 변경을 보류한다.

대안과 비용　교육용 도메인을 표시 시점에만 치환하면 원장은 보존되나 출력·화면 정책을 구분해야 한다.

인수 기준　표식 유무와 사용자 지정 이메일 유무를 교차한 fixture에서 사용자 주소 및 회사 설정 보존. 재초기화 시 동일.


## 현행 선택의 근거

월별 입력과 결과를 별도 스토어로 관리하는 점은 확정 후 마스터 변경과 월 장부의 분리를 지원한다. 주 스토어와 복합 인덱스를 유지하면 기존 백업 호환성에 유리하다. 모델의 실제 선택 근거는 config.ts와 main 통합 시험이며 개발 당시의 합의 기록은 확인되지 않았다.
