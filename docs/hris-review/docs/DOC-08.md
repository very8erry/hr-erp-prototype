# DOC-08　데이터 무결성·백업·복구 명세서

v1.0 · 2026-11-19 · b4aeb300270a62273d3d5f0c2fea87f2a09ba800

독자　저장 담당·운영자

목적과 범위　쓰기 실패와 데이터 교체 시 보존할 단위 및 인수 방법을 제시한다.


| 경계 | 현재 보존 수준 | 검증 또는 후속 시험 |
|---|---|---|
| 신규 등록·ATS | 회사·참조·사번을 같은 쓰기 거래에서 확인 후 복수 원장 add | 중복 제출·외부 조직 거부 후 원장 비교 |
| 근태 수정 | 입력 버전과 최신 레코드 대조·결과 삭제·로그가 한 거래 | 동시 두 요청에서 하나만 성공 |
| 급여 계산 | 결과·입력 상태·Run·로그는 한 거래. 원천 조회는 그 전에 수행 | 계산 직전 근태 갱신 경쟁은 별도 시험 필요 |
| 급여 상태 전이 | 상태와 로그 쓰기 분리 | A03 중단 주입 시 상태만 보존됨 |
| 전체 백업 | schemaVersion·exportedAt·data를 직렬화 | 복원 직전 파일의 출처·스키마·건수 대조 |
| 전체 복원 | seed에서 모든 스토어 clear·재적재를 한 거래로 묶음 | 중간 예외 후 기존 PK·데이터 비교 |
| 구버전 | v1 알 수 없는 Person을 거부, v2–6 및 현 버전 분기 | 기존 v6→v7 업그레이드 차단·구탭 종료·재시도 및 보존 기록 |


복구 절차는 가상 프로필에서 원본 백업을 확보하고 별도 프로필에 복원한 후 원장 키·기간·인원·급여 합계·로그를 비교하는 순서다. 업그레이드가 기존 탭으로 막히면 기존 연결을 닫고 초기화를 다시 시도한다. 전체 재적재의 원자성과 backup bundle을 읽는 순간의 일관성은 별도 문제다. 내보내기 중 변경을 허용할 때 스토어 간 동일 시점 보장은 별도 검증해야 한다. 사용자 데이터에 대한 실제 복원은 수행 범위 밖이다.
