# DOC-09　권한·보안 통제 정의서

v1.0 · 2026-11-19 · b4aeb300270a62273d3d5f0c2fea87f2a09ba800

독자　개인정보 담당·운영·PM

목적과 범위　실습 통제와 실제 자료 검토 전 필요한 통제를 대조한다.


| 대상 | AS-IS | TO-BE·인수 기준 |
|---|---|---|
| 역할·승인 | 저장 경로에서 HR_ADMIN·SYSTEM을 기록. 역할 명칭에서 인증된 개인 식별을 보장할 수 없음 | 역할별 허용 동작·승인자 결정 후 권한 없는 계정으로 읽기·쓰기·내보내기 거부 확인 |
| 최소 수집 | Person 연락처·가족·계좌·급여 기록 및 첨부를 취급 | 가상 식별자·마스킹으로 시연. 사용 목적별 필수 필드 목록과 삭제 책임 승인 |
| 백업·공유 | 전체 JSON 등 추출 가능. 브라우저 접근과 다운로드 파일의 경계가 다름 | 최소 필드 내보내기·파일 암호화·키 복구 정책. 테스트 자료로 복원 대조 |
| 감사 추적 | 일부 경로는 before/after 원문을 로그에 저장 | 사유·주체·시각·대상·버전만 필요한 경우 민감 문자열 제외. 변경·열람 권한 분리 |
| AI와 화면 기록 | 시뮬레이션 메뉴 비활성. 로그 수집 확장 미구현 | 가상 DB 격리, 시나리오 seed·규칙 버전, 최소 행동 이벤트. 녹화가 필요하면 가상 화면·보관기한·삭제 기준부터 승인 |
| 평가 객관성 | 승인된 성과 기준과 AI 평가 모듈 미확인 | 결과 정확성과 사용시간을 분리. 동일 난도·동일 자료로 반복 측정 후 사람의 판단 근거와 비교 |


실제 접근 주체별 부정 테스트나 보관기간의 법률 적합성 검증은 수행하지 않았다. 화면의 disabled 속성은 편집 편의와 상태 통제를 설명하지만 보안 주체의 인증 증거로 사용할 수 없다.
